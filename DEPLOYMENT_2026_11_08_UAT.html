UAT update, 2026-11-08 (Sunday)

Code 3d18fee9e on master. It goes over the 11-07 zip (2adb5a259), which is what UAT runs now. It brings the new report designer, the Power BI import, and the fixes found by running every feature against real Snowflake, Databricks and Jira accounts.

1 · What is in the zip

Everything changed since 2adb5a259: 76 backend files, 34 frontend files and 1 Spark file (111 in all). No chart files. Nothing to delete. No new Python or npm packages.

Nothing to run by hand in the database. One new column adds itself when the new API pod starts, empty: system_accounts.vault_field_map.

2 · Deploy, in this order

  1. Take a database backup so that a rollback is exact.
  2. Unzip over the source tree of your UAT deployment.
  3. Build these images and push them with the tag you deploy:
    ImageWhy
    querystudio-api (Dockerfile.api)Backend code. It also runs the feed worker, job worker and scheduler.
    querystudio-reports (Dockerfile.reports)Backend code
    querystudio-published-api (Dockerfile.published-api)Backend code
    UI image (Dockerfile.ui)Frontend code
    Spark job imagespark/jobs/generic_feed.py changed: a Snowflake feed that logs in with a key pair now runs on Spark. Without this rebuild such a feed fails on Spark; on the native engine it works either way.
  4. Roll out the new images the way you did for the last update.
After the deploy, each published API reads fresh data on its first request. Its cached answers are now tied to the API's exact definition (a fix: an API that reused an old id could be served the old API's rows), so the old cache entries are not used. This happens once.

5 · What to test (about 60 minutes)

  1. Designer. New report → Blank, pick a dataset, drag a field and a number onto a bar, a table and a number tile. Save, reopen, Preview. Run it and check one number against the source.
  2. Cloud + on-prem. New report, pick the cloud dataset, then + Same data from another source with the on-prem dataset of the same query. Check a total equals cloud plus on-prem. Add a date parameter and check it narrows both sides.
  3. Power BI. Import one of your own .pbix files on the dataset it uses. Read the preview's "not brought across" list, create, and compare two numbers with Power BI.
  4. Outline. On a report with an outline table, press Open all and Close all. Every opened row shows its own numbers.
  5. CSV. Download a report with a summed whole-number column as CSV. It shows 1000, not 1000.0.
  6. Share link. On a report over a table with row policies, open a share link and download the file. You get the plain sentence, not an error.
  7. Vault field names. On a Vault key-value System Account whose field names differ, fill Vault field names and press Test. It lists the fields it found and the login works.
  8. Snowflake. A published API over Snowflake SQL with a mixed-case column, filtered on that column. If you run Snowflake feeds on Spark with a key-pair login, run one (needs the new Spark image).
  9. Databricks (if you use it). Browse a schema with a view: it shows as a view. Run a long query in the SQL editor and press Cancel: it stops and says cancelled.
  10. Jira (if you use alerts). Put the Jira token in Vault, point the Jira System Account at it, and raise a test alert: one issue opens; a repeat does not open a second; clearing it closes the issue.
  11. Commentary and the 11-06 / 11-07 items are still to test from those guides; they are in this code too.

8 · Check after deploying (15 minutes)

  • Component Health is green.
  • Open an existing report and run it: the numbers are the same as before the deploy.
  • Open an existing published API twice: the first answer is fresh (see the note in section 2), the second is fast.
  • Admin → System Accounts opens, and an existing account's Test still passes.
  • Press Run now on a feed. It completes and the file arrives.

9 · If you must roll back

Deploy the previous images, or use helm rollback if the deployment changed through Helm. The new column can stay: older code does not read it, so the database needs no change. Reports made with the new designer, and Power BI imports, stay in the database; check them again once you are back on this code.
