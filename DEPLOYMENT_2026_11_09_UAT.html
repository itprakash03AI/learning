3 · What is new today

AreaWhat a person sees
Large queries in the backgroundBefore a big run QueryStudio counts the rows it will READ from the Iceberg file list (no data read). Above a threshold the run goes to the background: the screen says so ("up to N rows to read"), the bell shows it while it runs and again when it is ready, the result lands in the Download Centre, and E-mail me sends the person's own address a note when it is ready. The SQL editor's estimate shows the same count. Off until you set it -- there is no screen field yet for these two settings; set them as an admin with the API (they apply to every pod):
PUT /api/admin/app-config body {"features": {"background_rows_threshold": 5000000}} (0 = off)
PUT /api/admin/published-views/config body {"notify_email_domain": "corp.com"} (the mail goes to username@corp.com; "" clears it)
Installable appChrome / Edge offer Install QueryStudio: an icon and its own window. Nothing else changes.
Snowflake and Databricks "as of"A published API over Snowflake or Databricks can be read as of an earlier time (every table pinned to that one time, or refused in words). The API Explorer has a Read as of picker.
System Account Test (AWS portal)Test now logs in the way S3 does: with the portal address of the S3 connections that use the account (Admin → AWS Portal is no longer needed). With no connection using it yet, it says so. A database account (as Trino / Starburst use) can now be chosen for a portal connection, beside AWS Portal and AD accounts.
